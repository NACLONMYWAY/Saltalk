02本轮修掉的 3 个问题

问题 1 · 左上角多了一个白色方块 logo（按你的要求删除）

症状：标题栏 Saltalk 左边有一个 24×24 的反色方块。

处理：删掉 App.tsx 里的 .brand-mark 节点与 main.css 里对应的两条规则， 只留 Saltalk / Listening 字样。

问题 2 · 点击单词加入单词本时，被点中的词会「乱码」/ 右边多出一大段空白

症状：练习页点词后，那一个词的黑底块被拉成一条长条（看起来像乱码）； 历史页同样的操作表现为词右边凭空多出大量空白。两处共用一个对话组件，其实是同一个 bug。

根因（类名撞车）：可点单词的选中态写的是 class="w sel"，而 .sel 本来是 原生 select 的包装器。我的 .w.sel 只覆盖了颜色，display / flex 照单全收：

.sel   { display: inline-flex; flex: 1; min-width: 0; }  /* 给 select 用的 */
.w.sel { background: var(--ink); }                     /* 只改了颜色 */

在 display:flex; flex-wrap:wrap 的句子里，被点中的那个词于是成了唯一 flex-grow:1 的项目，吃掉整行剩余空间 —— 点哪个词，哪个词就变成长条。

定位：给诊断脚本加一段「取选中词的 getBoundingClientRect() 与相邻节点的 getComputedStyle().flex」探针，--dump-dom 一读就现形 —— 选中词宽 335px（正常 22px），flex 是 1 1 0%，而兄弟节点都是 0 1 auto。

修复：选中态改名 .w.picked，与 .sel 彻底分家。

防回归：新增 2 条守卫 —— 定点断言 .w.picked 存在 / .w.sel 不存在； 以及一条通用规则：条件状态类不许复用 main.css 里的结构类名。 变异测试：把 picked 改回 sel 报红 2 条，改成结构类 list 同样报红 2 条。

问题 3 · 背单词点「显示中文」看不到单词意思，只看到一段话 + 这段话的中文

症状：卡片背面显示的是一句英文例句和它的中文翻译，没有单词本身的中文释义。

根因（时序 + 快照）：加入单词本是「先快速插入、后台异步补释义」—— meaning 先写 null，网络回来后再回填。加完立刻去背，卡片背面就只剩例句；更糟的是卡片用的是 进入那一刻的快照，即使后台补好了也不会更新。

修复：

  • 背单词卡片改成只存 id、内容从 store 实时取 —— 释义补上后卡片自己更新，不再停在空快照上；
  • 新增「缺释义自愈」：进入单词本时后台补一次 meaning 为空的词（串行、限 5 条、带互斥锁）， 老数据也能自己长回来；
  • 释义没到位时，背面只显示「释义获取中…」，不再把例句顶上来冒充释义；
  • 给词典请求补 6 秒超时 —— 那台服务在国内常连不上，之前会把「加入单词本」挂住几十秒。

边界：这套修复没有改动 addWordToBook 的既有契约（仍是「快速插入、后台补全」）， service.test.ts 里锁定该行为的断言原样通过。

追加 · 点一下单词就直接看到它的意思（你的补充要求）

之前：点词只浮出一个「加入单词本」按钮 —— 想知道它什么意思，得先加进单词本、再去背单词里翻。

现在：点词立刻把释义摆在动作条里："Hi" /hi/ int. 你好；嗨（打招呼用语）。 已在单词本里的词直接读本地释义（按钮换成「已在单词本」）。

实现：新增 word:preview 通道（只查不落库），主进程侧带内存缓存。 快速连点不同的词时用请求序号丢弃过期响应，避免先发的慢请求把后点的词的释义盖掉。

对应新增状态图：查到（15 / 16）、查询中（18）、已在单词本（19）。

追加 2 · 点词「太鸡肋」：要等好久才出释义 —— 挖出 6 秒白等

症状：点一个词，释义要等很久才出现，功能形同虚设。

根因：查词是两步串行 —— 先调免费的 api.dictionaryapi.dev 拿英文释义与音标， 再调 Deepseek 翻成中文。而那个免费词典在国内网络下 DNS 被污染，连接建得起来但拿不到响应。 本机实测（design/profile-word-lookup.cjs）：

lookupWord(negotiate)  6005 ms → 超时失败
lookupWord(reception)  6017 ms → 超时失败
lookupWord(colleague)  6008 ms → 超时失败
translateWord(...)      385–731 ms → 正常

也就是说 3/3 全部卡满 6 秒超时，然后才开始第二步翻译 —— 每次点词固定白等 6 秒。 更讽刺的是：它查到的英文释义最后还会被中文翻译覆盖， 这个接口唯一的实际贡献只有音标。为了一个音标等 6 秒，就是「鸡肋」的根因。

修复：砍掉这个已不可用的词典，改成 Deepseek 一次请求同时返回「音标 + 中文释义」 （lookupWords，JSON 模式）。顺手加了预取：点第一个词时后台把整句的词一次查完， 之后点句中任何词都直接命中内存缓存。另外把「查不到不缓存」改成短 TTL 负缓存（60 秒）， 避免连点同一个生僻词反复打网络。

实测（node design/bench-word-lookup.mjs，真实网络）：

场景旧版现在
冷启动点第一个词≈ 6500 ms672–892 ms
再点同一个词≈ 6500 ms0 ms
点预取过的词≈ 6500 ms0 ms
预取整句 8 个词—一次请求 0.8–2.3 秒（后台跑，不挡界面）

取舍说明：src/main/dictionary.ts 与它的单测已归档到 design/_archived/removed-dictionary-module-1.4.6/（不是直接删，git 里也有历史）。 它在这台机器上 0% 可用，留着只会让后人误以为音标有第二个来源。

⚠️ 归档别放 dist/：electron-builder 打包时会清空输出目录下 不属于它自己的内容（这一版就踩了，见「遗留事项」）。

新增防回归：4 条 lookupWords/parseGlosses 单测 + 6 条 prefetchWords 单测，其中一条专门锁住「模型漏返回个别词时不许写负缓存」 —— 否则那个词会误显示「查不到释义」整整一分钟。

上一轮的历史案例（保留作守卫来源）：四六级倒计时环外面曾多出 3px 蓝色方框 —— 环的类名写成 class="ring"，撞上 Tailwind 内置工具类，而 box-shadow 没被覆盖。 这类问题类型检查、单测、肉眼 review 都抓不到，只能靠逐像素扫描发现， 于是有了 designSystem.test.ts 的第一批守卫。

05遗留事项

  • 点词释义需要联网：首次查一个没预取过的词约 0.7–0.9 秒（个别网络抖动时可能到 1.5 秒）。 点过第一个词之后，整句的词都已预取，再点就是 0 毫秒。已在单词本里的词不受影响（直接读本地）。
  • 预取会多发一次请求：点词时后台把整句最多 24 个词一次查完 —— 换来的是后续点词瞬时。 这一步不阻塞界面，失败也不提示。
  • 已存在的空释义词：自愈逻辑会在每次进入单词本时补，但若网络一直不可用，它会一直是 「释义获取中…」，此时删掉重加即可重试
  • 原型单文件 design/ui-preview.html 内仍叫 .ring；它自包含、无 Tailwind，不受影响，未改动
  • 打包 exe 请用 npm run dist；本机 PATHEXT 被削过，需走 win-electron-sqlite-build 技能里的 wrapper
  • eb-parked-dist/ 是绕开打包删除阈值用的暂存目录，确认不需要后可清理。 归档文件请放 design/_archived/，不要放 dist/ —— electron-builder 打包时会清空输出目录里不属于它的内容
